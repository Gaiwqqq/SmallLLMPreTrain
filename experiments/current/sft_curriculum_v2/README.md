## 为什么修改数据，而不是直接加轮数？

v1 所有训练大写任务都含 `label0...`，开发输入变成 `label1...`，模型经常把后者改回训练前缀。训练数值仅 10–69，开发数值变为 110–169；这种范围偏移混淆了格式学习和数值泛化。大量狭窄示范还使模型在不相关问题上输出姓名确认模板。

v2 大写任务使用随机字母数字串，训练、开发及诊断测试都使用相同的数值范围，实体与提示模板隔离。每项附无关的随机请求编号以确保有限模板实例不完全重复；该编号不应出现在目标回答中。生成后检查会话重复及 train/dev 重叠。

课程覆盖六类：两句日常建议、可核验加法、大小写/JSON/两个 bullet、礼貌改写、单句摘要、姓名/颜色/数量的多轮状态。算术不等于真实世界知识；这轮仍不能修复所有知识幻觉。模板覆盖有限，也不能用合成诊断宣称广泛语言能力。

32,000 个课程会话加 128,000 个原 SFT **训练划分**会话回放，按会话数为 20%/80%；长度不同，所以 token 比例不会恰好相同。回放帮助防止格式课程覆盖一般回复行为。两个旧候选都不作为起点，仍从原 `exports/chat` 初始化。

## 训练设置与成果判定

四卡 TRL 全参数 SFT，LR=3e-5，一轮，FP32 参数、BF16 计算、warmup 3%、cosine 调度。每卡 micro-batch=4、累积=4，全局 batch=64；160,000 个有效会话对应约 2,500 步。选择较小 micro-batch 是因为 GPU 0 仍运行已有聊天服务，需给原对话长样本留足显存。步数与耗时以实际 Trainer 日志为准。

先独立 CPU 预处理，再创建 NCCL 进程，延续已验证的 assistant-only mask、2048 截断、无 packing 和完整恢复快照。四卡使用端口 29643；控制器经 `nohup setsid` 脱离 SSH 会话。

这是一轮**纠正实验**：完成后先生成原 40 项一般开发回复及 600 项新课程诊断回复，并上传候选导出。仍需审阅一般回复是否恢复、格式和状态是否改善；不得仅凭 loss 或结构标记自动选优、更换服务或继续正式训练。

新的 120 项六类一般聊天验收题已在实验启动前冻结于 `evaluation/chat_test_v2.jsonl`，SHA-256 见同目录 manifest。它不加入训练、不用于当前选优；纠正实验脚本不会生成它的回答。通过开发审阅后再明确正式阶段配方，最终模型才使用该题集做逐题语义验收。
