# 正确性实验：四卡更新与尾部加权

## 问题与原因

多卡训练可能正常运行却更新错了。我们要检查相同全局数据是否产生接近单卡的更新，尤其是最后不足 batch 和空 rank 的情况。

## 为什么这样设计

使用小模型、FP32、相同初始化与 global batch，先降低数值与规模干扰。改变的是单卡/四卡执行方式，比较一次更新后的参数。特意加入不均匀尾部和没有样本的 rank，因为整除的数据容易掩盖错误。

每个 rank 的平均 loss 必须按真实样本数加权；DDP 平均梯度不是平均所有文档的天然替代。空 rank 用零权重 dummy 保持同步顺序，但不贡献真实训练 token。

## 结果与结论

四张 H20 的参数最大差异约 9e-8，空 rank 尾部通过。CPU 两 rank 对照也通过。浮点归约顺序允许小差异，不要求逐位相同。

当前加权和同步在受测条件与容限内成立。没有由此证明所有规模、所有 dtype 都正确，也没有证明四卡一定更快。下一步测恢复，再单独测性能。

证据：`runs/m03_gpu_correctness/summary.json`、`tests/integration/test_ddp.py`。原因与加权例子见 [分布式阶段](../../../docs/04_distributed.md)。
