# 输入验证：自训词表与真实数据容量

## 问题与原因

模型看到的是 token ID。若文档重复、验证混入训练、特殊 ID 错了或配额超过容量，后面的模型比较就没有可信输入。先把这些不确定性排除。

## 为什么这样设计

三个来源先全局去重，再按正文指纹划分；Tokenizer 只读训练文档。pilot 限定每来源接受 100,000 文档，用较小输入验证流程。完整版再处理所有所选分片，精确统计 token，而不靠下载字节数估算预算。

这里是输入正确性检查，不是混合比例的消融实验。70/25/5 有覆盖通用、解释和故事文本的动机，但没有实验支持它最优。

## 证据、结论与下一步

pilot 300,000 文档的指纹、分割、精确去重和编码往返通过。初始验证配额不足曾触发报错，改为先统计容量再打包。

全量 TinyStories 唯一训练容量约 3.895 亿；除以 5%，约束总混合预算为 77.9 亿，向下取为 77 亿。其他来源的剩余文本不能抵消这个比例约束。

结论是配额能真实满足、输入可追踪。不能证明所有语义重复已去除，不能证明数据或比例质量最优。下一步训练后观察模型表现。

证据：`runs/pilot-audit.json`、`data/capacities.json`、`data/tokenized/english/summary.json`。完整解释见 [数据与 Tokenizer](../../../docs/03_data_tokenizer.md)。
