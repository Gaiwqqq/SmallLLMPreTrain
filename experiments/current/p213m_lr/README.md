# 对照实验：新 Tokenizer 和语料下重新选择 LR

## 问题与原因

99M 的 LR=1e-3 是旧模型与旧数据的选择。213M 改了规模、词表、混合语料及 batch，必须重新做先导对照。

## 为什么这样设计

四张卡各做一个约 100M-token 任务：seed=2026 下 LR=3e-4/6e-4/1e-3，另做 6e-4、seed=2027。前三组保持初始化、输入预算、验证集及其他设置一致，主要改 LR；第四组帮助观察一次随机性变化。

使用独立初始化，而不是依次在同一个 checkpoint 上换 LR，否则后运行的组已多看数据，比较不公平。

## 实际结果

| LR | seed | 验证 loss |
|---|---:|---:|
| 3e-4 | 2026 | 5.988814 |
| 6e-4 | 2026 | 6.031944 |
| 1e-3 | 2026 | 6.136201 |
| 6e-4 | 2027 | 6.013090 |

选择 3e-4 进入正式训练。结论限定于短预算与当前设置，没有为每档做充分 seed 复核，不能证明长预算最优。

## 为什么还要看生成？

选出的 pilot 续写重复明显。最低验证 loss 不等于能完成用户请求；不同 Tokenizer 下的 loss 也不能拿来与 99M 数值排名。下一步验证更多唯一训练数据是否改善 Base，再做 SFT。

证据 `runs/m04_lr_pilot_*/summary.json`、`runs/lr-selection.json`、`runs/pilot-completions.json`，详见 [正式预训练](../../../docs/05_pretraining.md)。
