# 长实验：77 亿唯一 token 的 Base 预训练

## 问题与原因

100M-token pilot 接口通过但续写差。我们要观察同一架构在更大唯一数据预算下是否改善预测和生成，形成可用于 SFT 的 Base。

## 设计理由

使用约 213M 随机权重、自训 32K BPE、2048 上下文、70/25/5 混合。LR=3e-4 来自独立 pilot；global batch=256、micro=16 来自性能测量；四卡 DDP/BF16 计算/FP32 参数来自正确性验收。

20B 是计划上限，实际唯一容量受 TinyStories 的 5% 配额限制，故选择 7.7B；对齐后 7,699,996,672 输入 token，不重复凑预算。验证与测试文档不进入更新。

## 观察什么，怎样下结论

先检查有限 loss/梯度、恢复与完整预算；再检查同一验证集是否改善；最后用统一续写和辅助评测看重复、跑题和事实问题。只有前两项改善时，不能直接宣布会聊天。

**状态：正式训练已经启动，尚待最终结果。** 初始约 21.8 万 token/s 是更新吞吐，不能保证总耗时。完成和暂停状态由 [自动运行记录](../../../docs/results.md) 维护，本文不预写成功结论。

阶段产物是 Base、Tokenizer、完整恢复点和曲线。下一步先导出对照，再做真实对话 SFT。证据 `runs/pretraining-proposal.json`、`runs/m04_base/metrics.jsonl`，详见 [正式预训练](../../../docs/05_pretraining.md)。

截至第 1000 步的中期观察：已读 524,288,000 token，同一验证集 loss 由第 500 步的 4.368060 降为 3.582294，完整恢复点已保存。支持“预测有进展”，还不能判断最终沟通质量。
