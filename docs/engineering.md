## 设计与可执行步骤

模型只表达数学结构；数据模块只表达下载/清洗/编码/读取；训练模块显式表达 optimizer update；checkpoint 模块负责恢复、导出和发布。避免模型继承框架的复杂训练基类。

函数使用有意义的英文命名，核心接口标注类型；中文注释解释为什么这么做以及张量形状，不逐行翻译代码。错误在边界尽早抛出，不吞掉异常或悄悄降级。

配置分开模型和 recipe。Global batch 的单位是序列数；step 是 optimizer update；token 吞吐与有效预测位置分开记录。正式运行保存完整配置与数据指纹。

```bash
ruff check src/dummym tests scripts
ruff format --check src/dummym tests scripts
pytest tests -q
```

新增源码与测试统一格式。原教学入口保持兼容；不为美观改写数学行为或引入复杂抽象。测试重点是 loss/梯度正确性、尾部、恢复、数据隔离、模板和导出一致性。

每个阶段完成后审阅入口可追踪性、配置单位、重复代码、隐式全局状态、文档命令与实现一致性。关键修改通过验证后自动本地 commit；提交说明包含问题、行为与验证。README 同步到 ModelScope，但令牌和本地恢复产物不进入 Git。

本轮最多七天：环境与数据、基线/正确性、正式预训练约 96h、SFT、评测与交付。Scaling、Muon、MoE 和偏好优化留到后续。
