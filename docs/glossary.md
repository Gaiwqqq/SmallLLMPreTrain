# 术语表：先懂意思，再看缩写

这里的解释对应本项目实际实现。遇到术语可以先读一句话，回到实验报告后再看细节。

## 文本和模型

| 名词 | 易懂的解释 | 本项目中的例子 |
|---|---|---|
| token | 模型处理的文本单位，可以是词、词的一部分、标点或字节片段 | 不是固定“一词一个 token” |
| Tokenizer | 把文字变成整数 ID，也能把 ID 还原成文字的编码器 | 自训 32K ByteLevel BPE |
| BPE | 反复合并常见相邻片段，建立词表的办法 | 教学实现见 `tokenizer/bpe.py` |
| 词表 | 所有可用 token 及其 ID 的集合 | 32K 指约 32,000 个条目 |
| 参数、权重 | 模型训练会调整的数字 | 213M 指约 2.13 亿参数，M=百万 |
| embedding | 把一个整数 ID 变成一组可计算的数字 | `[B,T]` 变成 `[B,T,D]` |
| logits | 尚未转成概率的预测分数 | 每个位置对词表 V 个候选各给一个分数 |
| attention | 让当前位置从已经看到的内容中提取信息 | 预测下一 token 时不能读取未来 |
| 上下文长度 | 一次最多能处理的输入位置数 | 当前模型为 2048 |
| Base / Chat | 前者学习文章续写，后者额外学习对话回复 | 能续写不等于能按指令回答 |

`[B,T,D]` 是形状记号：B 是一次计算的序列数，T 是每条序列长度，D 是每个位置的表示维度。V 是词表大小。“张量”可以先理解为多维数组。

## 训练和比较

| 名词 | 易懂的解释 | 容易误解的地方 |
|---|---|---|
| loss | 预测与正确答案差距的数值，本项目使用交叉熵 | 不是聊天错误率，也不是准确率 |
| 梯度 | loss 对参数变化的敏感方向 | 优化器据此调整参数 |
| 反向传播 | 从 loss 反推各参数梯度的计算 | 还没有更新参数 |
| optimizer update / step | 优化器真正调整一次参数 | 不等于一次 forward，也不等于一个 token |
| 学习率 LR | 优化器更新幅度的主要控制量 | 太大、太小都可能不合适 |
| warmup | 开头逐渐增加学习率 | 本项目用更新步数或总步数比例描述 |
| cosine 衰减 | 按余弦曲线逐渐降低学习率 | 从峰值降到峰值的 10%，不是降到 0 |
| epoch | 遍历训练数据一遍 | 反复读同一小数据集不会增加唯一数据量 |
| seed | 固定随机过程的起点 | 会影响初始化和数据顺序，两个 seed 不证明普遍规律 |
| perplexity / PPL | `exp(loss)`，把平均预测不确定性换一种尺度表示 | 不同 Tokenizer 的 PPL 不宜直接比较 |
| checkpoint | 训练恢复点 | 只有权重时可推理，未必能准确接着训练 |
| RNG | 随机数生成器状态 | 恢复时只设 seed，未必回到中断时的位置 |

`1e-3=0.001`，`3e-4=0.0003`。B 在“7.7B token”里指十亿，因此 7.7B 是 77 亿个 token。

训练 loss 来自模型正在学习的文档；验证 loss 来自不用于更新参数的文档；测试集尽量留到最终验收，避免边看最终答案边调参数。

## GPU 与工程

| 名词 | 易懂的解释 | 为什么要关心 |
|---|---|---|
| micro-batch | 一张卡一次前向/反向处理的序列数 | 直接影响显存占用 |
| 梯度累积 | 多次计算梯度，再更新一次参数 | 小显存也能实现较大的有效 batch |
| global batch | 所有卡合起来一次更新使用的序列总数 | 改它会改变训练条件 |
| DDP | 每张卡放完整模型，分工读取数据，合并梯度 | 数据并行 |
| rank | 分布式进程的编号 | 四卡通常有 rank 0～3，编号不是额外 GPU |
| FSDP2 | 将参数、梯度和优化器状态等分片管理 | 降低每卡常驻状态的显存，但增加通信 |
| BF16 / FP32 | 两种数字表示精度 | BF16 计算省资源，FP32 更能保存细小更新 |
| SDPA | PyTorch 提供的 attention 计算接口 | 本项目调用它，后端选择合适的实现 |
| 吞吐 | 每秒处理多少 token | 更新吞吐与包含验证、保存的总耗时不同 |
| MiB / GiB | 按 1024 换算的容量单位 | 显存表需写清口径 |
| manifest | 记录文件来源、数量、配置和指纹的清单 | 证明实际读了什么 |
| SHA-256 | 为文件内容计算的指纹 | 内容变了，通常指纹也会变 |
| milestone | 留存的关键训练进度点 | 不被“只保留最近恢复点”的轮转删除 |
| HF 导出 | 转换为标准 Transformers 文件结构 | 先对照数学结果，再供 TRL/vLLM 使用 |

四卡 × 每卡 16 条 × 累积 4 次 = global batch 256。每条长 2048，则常规一步读取 `256×2048=524,288` 个输入 token；每条内部只预测后 2047 个位置，有效预测位置数略少。SFT 的会话长度变化，不能套用这个固定 token 公式。
