# 最终交付：训练与验收已完成，可靠聊天目标未达到

## 实际交付了什么？

完成了从随机权重出发的 213M 英文小模型工程：自行训练 Tokenizer，构建清洗/去重/packing 数据流水线，用四卡 PyTorch DDP 完成约 77 亿 token 预训练，再以 TRL 做 assistant-only SFT、学习率对照和课程纠正实验。原 Chat 和最终正式 Chat 导出及完整 Trainer 恢复快照均已上传私有 ModelScope。

最终正式 v2 SFT 从原 Chat 初始化，使用 160,000 个训练会话（按会话数 20% 六类课程、80% 原对话回放），LR=3e-5、两轮、四卡全局 batch=64，共 5,000 步。实际训练耗时 4,356.84 秒，train_loss=1.026046，课程验证 loss=0.130357。导出的 final 是 Trainer 按验证 loss 选择的模型，不是按最终 test 挑选模型。

本次不重复训练，也不重新生成回答来筛选好结果：读取已经生成的正式模型回复，核对冻结题集、题目/rubric、生成模型路径，再完整审阅 120 test +40 dev 项。

## 最终结论

**120 题通过 15 题，通过率 12.5%，accepted=false。** 目标要求总通过率 ≥70%、每类 ≥60%、结构正常率 ≥90%；目前没有任何语义类别达标。

| 类别 | 通过数 | 通过率 | 主要观察 |
|---|---:|---:|---|
| 日常交流 | 3/20 | 15% | 有少数友好短句，但长度限制、相关性和意图不稳定 |
| 基础知识 | 4/20 | 20% | 碳符号、听觉等少数正确，大量简单知识仍错 |
| 指令遵循 | 3/20 | 15% | YES、提问、固定问候正确；大小写、JSON、计数等失败 |
| 礼貌改写 | 3/20 | 15% | 多数误触发隐私声明，未完成原请求 |
| 单句摘要 | 2/20 | 10% | 常遗漏费用或编造志愿者数量、套餐、时间等事实 |
| 多轮状态 | 0/20 | 0% | 姓名被当作 assistant 身份，数量更新错误且相互矛盾 |

只有 3 题触发自动复读标记，结构正常率 **117/120=97.5%**。其余“没有明显结构异常”的回复也可能答错事实或任务，所以结构率达标不能替代语义验收。

40 题 dev 单独通过 **9/40=22.5%**，不并入最终分数。开发集中原文已很短的摘要允许最低限度原意保留，因此六个复制原文的摘要通过；这不证明真正的摘要压缩能力。最终 test 明确要求一整句、保留所有主要事实且无编造，采用更具体的 rubric。

## 评分如何保证可审阅？

120 项最终回答和 40 项开发回答都已逐轮读取，保存每题的布尔判定与实际依据。评分由 Codex 辅助，**尚非独立人工认证**。日常相关性、错误严重性与边界题仍含判断成分。

没有只匹配关键词。例如金符号回答 C 失败；whale 同时说鱼和哺乳动物失败；摘要即使写对时间和费用，编造一百名志愿者仍失败。上下文中偶然出现正确总数，但同时给出冲突状态，仍失败。

对参考答案也保留合理替代：切纸工具回答 knife 按功能通过，而不是因为没写 scissors 就失败。两点桌面整理给出了编号列表；因题目明确要求 bullet，按冻结格式判失败。若放宽这一边界，仅多一题，结论仍远低于目标。具体政策与边界项见 [评分方法](../evaluation/reviews/formal_v2/review-method.json)。

## 为什么低 loss 没带来可靠交流？

验证 loss 衡量模型能否预测课程模板中的 assistant 示范。v2 的 600 项验证仍是有限模板家族，且短回复有重复的格式结构。模型可以学到这些局部规律，但新措辞、新的语义角色、复杂状态更新和真实世界知识仍可能失败。这是本次观察，不是对唯一原因的证明。

正式两轮没有解决开发题暴露的基础能力与状态问题。四卡训练、恢复和上传正确，说明工程可运行；它们不证明数据质量、课程覆盖或模型学习能力已足够。没有对照证据时，不能把失败全部归于参数规模，也不能断言只要继续加轮数就能修复。

首轮 test 通过率为 38.3%，此次为 12.5%，**两套题不同且具体约束不同，不能直接宣称能力下降 25.8 个百分点**。同一 40 题开发集原 Chat 10/40、纠正实验 10/40、正式模型 9/40；小样本和评分边界也限制了对轻微差异的解释。

## 模型与服务的边界

正式候选位于训练机 `/diff/gaiwq/llm_pretrain/exports/curriculum-v2-formal`。本次核验依据来自该正式模型的离线生成记录，而不是当前 8000 端口旧 `exports/chat` 服务。无需为了读已有回答重新切换服务；现有服务权重没有被本次验收替换。

[ModelScope 私有项目](https://modelscope.cn/models/GaiWeiqi/SmallLLMPreTrain-English) 保存模型及恢复点；最终原始回复、逐题理由、汇总报告、评分政策和权重哈希归档在 `reports/final-v2/`，正式模型卡注明未达标。学习用途可下载检查，尚不适合可靠事实回答或需要状态正确的应用。

## 后续如果继续，应该先验证什么？

本轮以真实未达标结果收尾，没有自动再开新训练。后续先审查基础模型的续写与 token 预测、Tokenizer 对数字/实体的切分、训练数据质量及角色/监督边界，再用小规模可核验对照确认有效方向。应增加任务与表达的覆盖，避免以复制或固定模板高分代替泛化。

当前 test 已被审阅，后续迭代只能把它当历史回归集；新的独立验收题必须重新冻结。追加训练范围与预算另行确定。
